# 02 — 架构设计（serial-pro-rs）

## 1. 总体

Rust workspace，两 crate 严格分层（延续 putty-rs / com0com-pro 的工程模式）：

```
serial-pro-rs/
├── docs/                    需求/架构/计划
├── crates/
│   ├── sp-core/             无 UI 依赖的引擎库（可独立测试）
│   │   ├── config.rs        PortConfig / Settings / QuickSendItem（JSON 持久化）
│   │   ├── channel.rs       通道事件与命令协议（P2 扩展为通用通道）
│   │   ├── serial.rs        串口工作线程（聚包读 + 发送 + 事件上报）
│   │   ├── hexutil.rs       Hex 解析/格式化/控制字符可视化
│   │   └── error.rs
│   └── sp-ui/               egui 界面（eframe）
│       └── main.rs          面板布局 / 事件泵 / 设置联动
```

## 2. 数据流（P0 串口）

```
[串口硬件]
   │ serialport crate (timeout 20ms)
   ▼
SerialWorker 线程（每端口一个，spawn_serial）
   ├─ 读：首包到达后进入聚包窗口：循环 read 直到 idle(pack_timeout) 或 10KB 上限
   │    pack_timeout < 0 → 流模式（无窗口，读到即发）
   ├─ 写：cmd_rx.recv_timeout(20ms) 取 Send/Close 命令 → write_all
   └─ 事件 → crossbeam-channel event_tx：Opened / Rx(bytes) / TxEcho / Closed / Error
   ▼
SerialHub（sp-core）：HashMap<id, ActiveSerial> 管理 N 个端口，poll() 排水事件
   ▼
sp-ui（每帧 poll）：事件 → RxRecord{ts, dir, bytes} 环形缓冲(默认 2000 条)
   → egui ScrollArea 渲染（RX 绿 / TX 红色，文本|Hex 双显）
```

关键决策：
- **显示层环形淘汰**（NFR-2）：llcom 用熔断/清屏、SuperCom 用内存看门狗换 TextEditor，
  两者都是被动补救；本方案在缓冲层直接淘汰最旧记录，渲染层用 ScrollArea + 每帧限量绘制。
- **线程模型**：串口线程持有 port 句柄，UI 线程绝不触碰；关闭 = 发 Close 命令由线程自行退出后
  join，规避 .NET SerialPort.Dispose 卡死那类问题（serialport crate 同步 Drop 无此坑）。
- **panic 隔离**（NFR-3）：worker 闭包外层 catch_unwind，异常时发 Error 事件而非进程崩溃。

## 3. 通道协议（channel.rs，P2 通用化的地基）

```rust
enum ChannelEvent { Opened(id), Rx(id, bytes), TxEcho(id, bytes), Closed(id, reason), Error(id, msg) }
enum ChannelCommand { Send(bytes), Close }        // P2: SetParams/Subscribe...
trait Channel  // P2: SerialChannel / TcpChannel / MqttChannel / PipeChannel
```

P0 只有 SerialChannel，但事件/命令协议按通用通道设计，P2 加新通道不改 UI 泵。

## 4. 脚本钩子（P2 设计预留）

- mlua 5.4 + Luau 风格沙箱：移除 os/io 危险库；脚本缓存 load 结果；每脚本步数预算
  （llcom LuaLoader 的 runLimit 思路）。
- 管道位置：UI 发送 → `send_hook(bytes) -> bytes` → 通道；通道 Rx → `recv_hook(bytes) -> bytes`
  → 显示缓冲。钩子可 per-port 独立配置。
- 通用通道 API：`api_send(channel_name, bytes)` / `api_on(channel_name, fn)`——对齐 llcom 的
  SendChannelsRegister 设计。

## 5. 配置持久化（config.rs）

- 位置：exe 目录便携优先，否则 `%APPDATA%\serial-pro-rs\settings.json`（MSIX 式双路径策略，
  参考 llcom 但去掉商店特判复杂度）
- 内容：每端口 PortConfig 记忆（波特率/校验/分包超时/Hex 开关/字体）、快捷发送条目、窗口状态
- 写盘策略：**显式动作触发**（改参数/编辑快捷发送/关窗），不做属性 setter 全量写盘
  （llcom 的 IO 放大教训）；写前滚动 .bak。

## 6. UI 布局（egui）

```
┌ TopPanel: 端口选择 + 刷新 + 波特率/数据位/校验/停止位 + 分包超时 + [打开/关闭] ┐
├ SidePanel(right): 快捷发送（条目列表：点击发送/✕删除/内联编辑）              │
├ CentralPanel: RX 记录流（时间戳 + 方向 + 内容，文本/Hex 切换，暂停滚屏）      │
├ BottomPanel: 发送框 + Hex 勾选 + [发送] + 历史(↑↓)                          │
└ 底部状态条: RX/TX 计数 · 打开端口数 · 最后错误                               ┘
```

字体：msyh.ttc → simhei → simsun 回退链（ccp-gui 已验证方案）。

## 7. 测试策略

- sp-core：单元测试（hex 解析、聚包窗口纯函数、配置往返、控制字符表）
- 串口收发 E2E：依赖真实/虚拟串口（com0com CNCA0/CNCB0），标 `#[ignore]` 手动跑
- sp-ui：不做自动化，人工验收清单（docs/03）
