## 2. 通道模型（实际实现：worker + hub，非 trait）

每类通道一个 worker 函数，共享同一事件/命令协议；`SerialHub` 以 id 索引持有激活通道：

```
enum ChannelEvent  { Opened(id), Rx(id, bytes), TxEcho(id, bytes), Closed(id, reason), Error(id, msg) }
enum ChannelCommand{ Send(bytes), Close }
struct SerialHub   { next_id, active: HashMap<id, ActiveSerial> }
  → open / open_tcp_client / open_tcp_server / open_udp / open_mqtt / open_winusb / close
```

- **worker 模式**：每通道一条线程 + `catch_unwind` 隔离；命令通道 crossbeam 非阻塞轮询，
  数据读用短超时（20ms）避免卡 Close。
- **MQTT 特例**：rumqttc 同步 `Connection.recv()` 是阻塞迭代，拆双线程——收包线程阻塞
  转发 Publish→Rx，控制线程轮询命令→publish（Client 可 Clone）。
- **WinUSB**：rusb 0.9 vendored（静态 libusb），打开 VID:PID 设备后自动定位第一个
  bulk IN/OUT 端点对；读 20ms 轮询。Windows 侧要求设备驱动为 WinUSB/libusb（Zadig）。
- 原设计中"trait Channel 抽象"未采用：六类通道差异大（聚包/多客户端/主题/端点），
  枚举式 hub 方法比 trait 对象更直接；协议层统一已足够保证 UI 事件泵零改动。

## 3. 数据流（串口通道）

```
[串口硬件]
   │ serialport crate (timeout 20ms)
   ▼
SerialWorker 线程（每端口一个，spawn_serial）
   ├─ 读：首包到达后进入聚包窗口：循环 read 直到 idle(pack_timeout) 或 10KB 上限
   │    pack_timeout < 0 → 流模式（无窗口，读到即发）
   ├─ 写：cmd_rx 轮询取 Send/Close 命令 → write_all + flush
   └─ 事件 → crossbeam event_tx：Opened / Rx / TxEcho / Closed / Error
   ▼
SerialHub（sp-core）：HashMap<id, ActiveSerial> 管理 N 个通道
   ▼
sp-ui（每帧 poll_channels）：事件 → RxRecord{ts, dir, bytes} 环形缓冲(2000 条)
   →（可选）Lua recv_hook → 接收区渲染（TX 红 / RX 绿，文本|Hex|ANSI 三态显示）
   →（可选）plot 数值提取 → 示波器曲线
   →（可选）LogWriter 落盘（模板 + MB 分片）
```

关键决策：
- **显示层环形淘汰**（NFR-2）：在缓冲层直接淘汰最旧记录，渲染层每帧限量绘制最后 500 条。
- **线程模型**：串口线程持有 port 句柄，UI 线程绝不触碰；关闭 = 发 Close 命令由线程自行退出。
- **panic 隔离**（NFR-3）：worker 闭包外层 catch_unwind，异常时发 Error 事件而非进程崩溃。

## 4. Lua 双向钩子（hooks.rs 实际语义）

- mlua 0.10（Lua 5.4 vendored）。脚本定义 `on_send(data)` / `on_recv(data)`：
  返回新字符串/字节串即替换数据，返回 nil 透传。
- 工具表 `sp.hex(bytes)` / `sp.fromhex(str)` / `sp.log(...)`；脚本 `print` 重定向到
  "脚本输出"面板（注册表收集）。
- 管道位置：UI 发送 → `on_send` → 通道；通道 Rx → `on_recv` → 显示缓冲（全局，非 per-port）。
- 容错：重载脚本编译失败时**保留旧脚本继续工作**；钩子禁用时完全直通。
- 与原设计的差异：未做 os/io 危险库移除与步数预算（脚本由用户本地自写，威胁模型可接受；
  若做脚本分享/市场必须补沙箱）；未做 per-port 独立钩子与多通道 api_send。

## 5. 配置持久化（config.rs）

- 位置：exe 目录便携优先，否则 `%APPDATA%\serial-pro-rs\settings.json`
- 内容：每端口 PortConfig 记忆、快捷发送多页（10 页 + 页名）、日志/帧/队列/定时配置、
  Lua 脚本与启用开关、通道类型与各通道参数（TCP/UDP/MQTT/USB 地址）、界面语言
- 写盘策略：**显式动作触发**（改参数/编辑/开闭通道/退出），不做属性 setter 全量写盘；
  读失败时回退 `.bakup`

## 7. 串口监听（serial_monitor / serial_monitor_hook）

- 注入器（stable）枚举目标进程 → LoadLibrary 注入 hook DLL → DLL 内 retour static-detour
  挂 ReadFile/WriteFile，按 COM 号过滤后经 C 回调（packed 结构跨 ABI）→ crossbeam 通道 → UI。
- hook DLL 依赖 nightly（retour static-detour），**独立 workspace**：
  `cargo +nightly build --release --manifest-path crates/serial_monitor_hook/Cargo.toml`，
  产物由 serial_monitor 的 build.rs 嵌入主程序（include_bytes）。
- 限制：需管理员权限；仅支持 64 位目标进程。
